# 실시간 주차와 만차 대체 안내

식당 주변 주차장을 찾으면 **빈자리 확인 → 미확인 → 만차** 순서로 제안한다. 최신 빈자리가 확인된 주차장을 우선 추천하고, 안내 직전 선택한 곳을 다시 조회한다. 조회 결과가 없거나 오래됐다는 이유로 주차 가능 또는 만차를 추정하지 않는다.

## 제공 지역과 자료

**서울·강릉·부산·서귀포·대구·인천·여수, 7개 도시의 공식 공급 자료**를 연결한다. 각 공급 시설 중 Kakao 장소와 일치하고 수량·시각 검증을 통과한 곳에만 빈자리를 표시한다. **7개 도시 전체 주차장이나 전국 빈자리 제공을 뜻하지 않는다.**

| 지역 | 공식 출처와 조회 자료 | 시간 기준 |
|---|---|---|
| 서울 | [서울열린데이터광장 시영주차장 실시간 정보 OA-21709](https://data.seoul.go.kr/dataList/OA-21709/A/1/datasetView.do) 공개 Sheet, [안내 정보 OA-13122](https://data.seoul.go.kr/dataList/OA-13122/S/1/datasetView.do)의 코드·좌표 대조 | 실제 제공 관측 시각, 10분 이내 |
| 강릉 | [강릉시 도시정보센터 주차정보](https://its.gn.go.kr/parking/ParkingInfo)의 공개 지도 목록과 시설별 상세 현황 | 관측 시각 미제공, 실제 조회 완료 후 90초 이내 |
| 부산 | [부산시설공단 통합주차포털](https://bsparking.bisco.or.kr/realtimeparking)의 공개 실시간 목록 | 관측 시각 미제공, 실제 조회 완료 후 90초 이내 |

| 인천 | [인천시설공단 실시간 주차 현황](https://smartparking.insiseol.or.kr/realtimeparking)의 공개 목록 중 공식 화면의 공영·연계 시설 | 관측 시각 미제공, 실제 조회 완료 후 90초 이내 |
| 여수 | [여수시도시관리공단 주차포털](https://parking.yumcorp.or.kr/parking/realtime)의 공개 실시간 목록 중 제공 대상 시설 | 관측 시각 미제공, 실제 조회 완료 후 90초 이내 |

서울의 안내 자료 자체에 있는 과거 현재주차대수 컬럼은 실시간 공급원으로 사용하지 않는다. 서울 공식 페이지도 현장과 5분 이상 차이가 날 수 있다고 안내한다. 제주 연결은 **서귀포 공급 시설**에 한정한다. 제주 ITS의 공개 8개 기록은 현재 연계 상태를 확인할 수 없고 오래된 `UPDT_DT`가 시설 메타데이터 갱신 시각일 수 있어 사용하지 않는다. 제주시 전체나 제주도 전역을 활성화한 것으로 표시하지 않는다.

이 연결에는 추가 주차 API 키가 필요 없다. 공식 공개 화면이 제공하는 GET·POST 조회를 사용하고, 로그인 세션이나 사이트에 포함된 제3자 비밀키를 가져오지 않는다. 공급처와 출처 링크를 화면에 표시한다. 서울 자료의 공공누리 표기는 해당 데이터 페이지의 조건이며, 다른 도시 자료에 공공누리·자유 이용 허가가 있다고 확대해 주장하지 않는다.

Kakao Local은 관광지·식당 주변 3km의 등록 주차장 위치를 찾는 데 사용한다. 공급 자료와 정규화한 이름을 비교하고 좌표가 검색 장소 150m 이내인 경우에만 결합한다. 서울은 동일 공급 코드의 안내 좌표도 대조한다. 일부 명칭 차이는 확인된 시설 ID·주소를 함께 묶은 개별 별칭으로만 처리하며, 번호·방향이 다른 주차장을 일반 규칙으로 합치지 않는다. 모호한 중복 후보나 위치가 일치하지 않는 곳의 수용면을 빌려 쓰지 않는다. 공급 범위 밖이나 매칭되지 않은 주차장은 위치 검색을 유지하면서 빈자리를 미확인으로 표시한다.

## 빈자리 판단

| 상태 | 조건 | 안내 동작 |
|---|---|---|
| 빈자리 확인 | 제공 대상 자료, 유효한 수용면·잔여면, 관측 10분 또는 조회 90초 이내, 잔여면 1대 이상 | 시간 기준을 표시하고 우선 추천, 안내 직전 재조회 |
| 만차 | 같은 검증을 통과한 잔여면 0대 | 자동 대체 후보를 찾고 해당 만차 주차장으로 새 안내를 시작하지 않음 |
| 미확인 | 공급 범위 밖, 매칭 실패, 연결 실패, 잘못된 값·시각, 해당 시간 기준 초과 | 빈자리나 만차로 간주하지 않음; 위치 안내는 사용자가 별도로 선택 |

수량 필드의 뜻은 제공처별로 확인한다. 서울은 전체 수용면에서 현재 주차대수를, 강릉은 `totalSpace`에서 `occupancy`를 뺀다. **부산·서귀포·인천·여수의 `parkCount`는 공식 화면에서 잔여면으로 표시하는 값**이므로 다시 전체 면수에서 빼지 않는다. 대구는 시설 유형별 상세 잔여면을 사용한다. 음수·비정수·수용면보다 큰 잔여면, 충돌하는 수량, 연계 대상이 아닌 자료와 미래 시각은 사용하지 않는다. 오래된 관찰과 실패 응답에는 빈자리 수를 넣지 않는다. 관광버스·화물 등 제한 시설은 확인 가능한 조건으로 제외하며 무료 이용·운영시간·실제 입구·방문 자격을 잔여면에서 추정하지 않는다.

실시간 원본과 강릉의 통신 상태 포함 지도 목록은 **30초** 캐시하고, 서울의 별도 위치 대조 자료는 24시간 캐시한다. **실제 공급처 조회 완료 시각 `retrievedAt`은 캐시를 읽을 때 갱신하지 않는다.** 응답 평가 시각 `fetchedAt`만 현재 시각으로 갱신해 유효기간을 다시 평가한다. Android는 서버 응답 시점의 자료 나이에 수신 이후의 단조 증가 시간을 더한다. 기기의 시계나 시간대를 바꿔도 이미 받은 정보를 계속 새 정보처럼 취급하지 않는다.

관측 시각이 없는 공개 실시간 응답은 **조회 시각 기준 현황**이다. `observedAt`은 `null`, `timeBasis`는 `retrieved`로 유지하고 화면에 조회 시각과 **제공처 갱신 시각 미제공**을 표시한다. 응답 봉투의 생성 시각이나 시설 메타데이터 수정 시각을 센서 관측 시각으로 바꾸지 않는다. 최근에 조회했다는 사실은 공급처 센서가 최근에 갱신됐다는 보증이 아니다.

`parkingStatus`는 `available`, `full`, `unknown` 중 하나다. 각 장소의 `parking` 객체에는 같은 `status`, `availableSpaces`, `totalSpaces`, `observedAt`, `fetchedAt`, `source`, `sourceUrl`, `reason`, `providerId`가 들어간다. 조회 기준 현황에는 실제 `retrievedAt`과 `timeBasis: "retrieved"`가 필수다. 관측 기준은 `timeBasis: "observed"`이며 기존 서울 응답처럼 이 필드가 없으면 관측 기준으로 해석한다. `reason`은 `live`, `stale`, `unmatched`, `unavailable`, `unsupported`로 구분한다. 값이 없는 수치·관찰 시각·공급 ID는 `null`이며, 미조회 응답의 `retrievedAt`·`timeBasis`는 없을 수 있다.

## 목록과 안내 직전 재확인

1. 식당 선택 직후 주변 주차장을 조회한다. Kakao 검색은 전체 12초 제한 안에서 최대 **3페이지·45개**를 확인한 뒤 최종 10개를 보여 준다. 추가 페이지 조회가 실패하면 확인한 후보를 사용한다. 빈자리 확인된 후보가 먼저 표시되며 미확인 후보 안에서는 공영·공공 표기와 거리를 참고한다.
2. 주차 목록이 열려 있고 조작 가능한 정차 상태이면 **45초마다** 갱신한다. 목록에 잔여면, 제공처 관측 시각 또는 조회 시각과 출처를 표시하며 자동 새로고침 시 스크롤 위치를 보존한다.
3. 안내 버튼을 누르면 선택한 장소 ID를 `focusId`로 보내 재조회한다. 해당 장소가 만차가 되어 상위 10개에서 빠져도 `focus` 응답으로 현재 상태를 확인한다.
4. 정차 상태에서 사용자가 안내를 시작할 때 선택한 주차장이 만차이면 같은 응답에서 빈자리가 확인된 다른 후보로 안내하고 변경 이유를 알린다. 이 단계에서는 유효한 조회 기준 현황도 사용할 수 있다. 대안이 없으면 임의의 미확인 장소로 바꾸지 않는다.
5. 빈자리 미확인 후보는 별도 확인 화면의 **위치로 안내**를 선택했을 때만 등록 위치로 안내한다. 이 선택은 빈자리 확인 성공을 뜻하지 않는다.

식당 자체 주차 메모는 사용자가 직접 확인한 기록이며 실시간 공급 데이터와 별도로 유지한다. 경로 화면의 수동 "만차·입차 불가" 버튼은 없앴다. 만차 판단과 대체 제안은 위 자동 확인과 사용자 수락으로만 이루어진다.

시설별 추가 상세 조회는 강릉 최대 6곳·동시 3개, 대구 최대 30곳·동시 4개로 제한한다. 도시별 공급 조회에도 8초 제한을 둔다. 후보가 많아 상세 조회 대상에 들지 못한 곳을 빈자리로 추정하지 않는다.

## 순정 내비 안내 중 확인

사용자가 주차장 안내를 시작하면 Android foreground service가 Pleos 내비 화면에서도 **1분 간격**으로 확인한다. 앱에서 상태와 중단 버튼을 제공하며 알림 권한이 있으면 알림에서도 중단할 수 있다. 서비스는 시스템 종료 후 자동으로 재시작하지 않는다.

### 변경 제안 (사용자가 수락해야 변경)

서비스는 목적지를 조용히 바꾸지 않고 **제안**한다. 다음 중 하나이면 더 여유 있는 주차장으로 바꿀지 알림(변경·유지 버튼)과 앱 배너로 묻는다.

- **만차**: 현재 주차장의 잔여면이 0으로 확인됨
- **곧 만차**: 현재 주차장의 잔여면이 5면 이하이거나 전체의 5% 이하

제안 근거와 대체 후보 조건은 다음과 같다.

- 현재 주차장 값은 유효기간 안이어야 한다(관측 기준 10분, 조회 기준 90초). 조회 기준 공식 현황도 근거가 되며, 수락은 사용자가 결정한다.
- 대체 주차장은 같은 유효기간 안에서 빈자리가 확인되고 자신도 "곧 만차"가 아니어야 한다. 현재가 "곧 만차"일 때는 현재보다 잔여면이 많아야 한다. 이미 제외하거나 안내했던 곳은 제외한다.
- 대체 장소까지의 Kakao 도로 응답이 유효하고 끝점이 장소 좌표 150m 이내여야 한다.
- 사용자가 "유지"를 누른 같은 조합(대체 주차장+만차/곧 만차 단계)은 다시 제안하지 않는다. 곧 만차에서 만차가 되면 다시 제안한다.

**변경**을 누르면 빈자리를 한 번 더 확인한 뒤 Pleos에 대체 목적지를 요청한다. 그 사이 값이 오래되거나 사라지면 변경하지 않고 이유를 표시한다. 순정 내비는 **차량 현재 위치**에서 다시 탐색하며, 대체 목적지 응답까지 확인한 뒤 앱 여정에 반영한다. 순정 내비의 현재 목적지 이름·좌표가 앱이 안내한 주차장과 일치해야 하며, 사용자가 다른 목적지로 바꿨거나 안내를 종료했거나 도착한 경우 확인을 중단한다. 네트워크 오류·오래된 관찰·대안 없음·도로 확인 실패 시 기존 안내를 유지하고 이유를 표시한다.

사용자가 설정에서 **다른 앱 위에 표시**를 허용하면 제안 카드(변경·유지 버튼)가 순정 내비 화면 위, 회전 안내와 2D 버튼을 가리지 않는 오른쪽에 뜬다. 허용하지 않으면 알림과 앱 배너만 쓴다. 에뮬레이터에서만 확인했으며 Pleos 차량의 권한 정책과 주행 중 조작 제한은 확인하지 않았다.

관측 시각이 없는 조회 기준 공급원(강릉·부산·서귀포·인천·여수 등)도 제안 근거로 쓸 수 있지만 **사용자의 수락 없이는 목적지를 바꾸지 않는다.**
한 번 시작한 확인은 최대 **3시간**, 수락한 목적지 변경은 최대 **3회**이며 변경 사이에는 최소 **2분**을 둔다. 반복 변경으로 같은 주차장을 왕복하지 않도록 이미 안내했던 후보를 제외한다. 제안과 별개로 사용자가 앱 또는 알림의 중단 버튼을 누르면 확인 서비스만 중단하고 내비 안내는 유지한다.

순정 내비와의 초기 연결에서는 새 경로 이벤트와 실제 목적지를 확인한다. SDK 응답을 확인하지 못하면 자동 확인을 중단하며, 이전 경로의 취소 이벤트를 새 안내 실패로 단정하지 않는다. 다른 목적지를 덮어쓰지 않기 위해 목적지 변경 직전에도 내비 상태를 다시 읽는다.

## 검증 범위

자동 검사는 빈자리·만차·미확인 분리, 제공처별 수량 의미, 잘못된 수치와 시각, 30초 캐시·관측 10분·조회 90초 만료, 시계 차이, 이름·좌표 매칭, 상위 목록 밖 `focus`, 정차 시 대체와 관측 시각 필수인 주행 중 대체의 구분을 포함한다. 공개 데이터의 현재 응답, 에뮬레이터 화면, 실제 Pleos 목적지 변경, 제어된 만차 응답 시연은 서로 구분해 기록한다. 최신 실행 결과와 CI는 [검증 기록](VALIDATION.md) 및 해당 변경 브랜치의 Actions 결과에서 확인한다. 이 문서는 실제 차량 주행 또는 현장 입차 성공을 주장하지 않는다.

## 서버 실행 환경

Node.js **22.19 이상인 22 계열 또는 24.6 이상**을 사용한다. `npm start`와 Windows 실행기는 `--use-system-ca`로 운영체제의 신뢰 인증서를 함께 사용한다. HTTPS 인증서·호스트 검증은 유지하며 인증서 검증을 끄는 옵션을 사용하지 않는다. 주차 연결용 추가 키는 필요 없고, 주변 장소 검색과 도로 조회의 기존 Kakao 키는 계속 필요하다.
## 한국교통안전공단 보조 연동 (선택)

DATA_GO_KR_KEY를 설정하면 [한국교통안전공단 주차정보 API(15099883)](https://www.data.go.kr/data/15099883/openapi.do)의 실시간 잔여면을 **가장 낮은 우선순위의 보조 출처**로 사용한다. 위 지자체 출처가 이미 빈자리나 만차를 확인한 장소는 바꾸지 않고, 확인되지 않은 장소에만 채운다. 키가 없거나 조회가 실패하면 아무것도 바뀌지 않는다.

- 이 API는 시설 ID·잔여면·전체면만 주고 위치와 관측 시각을 주지 않는다. 위치는 catalog/parking-facilities.json(scripts/build-parking-facilities.mjs로 생성, 기본 부산·서울 253곳)에서 가져오고, Kakao 장소와는 **이름이 비슷하고 150m 이내**일 때만, 시설과 장소가 일대일일 때만 결합한다.
- 관측 시각이 없으므로 	imeBasis: "retrieved"(조회 시각 기준, 90초 이내)이며 화면에 "제공처 갱신 시각 미제공"으로 표시한다. 따라서 **주행 중 자동 목적지 변경의 근거로 쓰지 않는다.**
- 카탈로그에 없는 지역은 계속 미확인이다. 전국 빈자리를 제공한다는 뜻이 아니다.
