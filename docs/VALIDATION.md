3. 관광지 주변 맛집에서 **초당두부** 조건을 선택하고 실제 검색 결과 **고향산천초당순두부**를 골랐다. 식당 선택 직후 주차장 조회가 자동으로 시작됐다.

## 실제 데이터 누락과 주차 추천 보완

- 강릉 위치 기반 TourAPI 목록에서 기존 풍경 관광지의 일부가 누락되는 현상을 확인했다. 후보가 적으면 원본 스냅샷과 카탈로그의 주변 장소 ID를 단서로 최대 8개 `detailCommon2` 조회를 수행한다. 화면에 사용할 사진·좌표·반경·ID·제1유형 조건은 최신 응답으로 다시 검증하며 저장 사진이나 제3유형 이미지를 대신 쓰지 않는다.

- 최초 거리순 주차 결과에서는 **107m의 카페오션스강릉수제버거 경포대점 주차장**이 **180m의 강문해변 제2공영주차장**보다 앞섰다. 이를 수정해 가까운 15개 중 공영·공공·시영·구영·군영 표기를 우선하고 같은 분류 안에서 거리순 정렬한 10개를 표시한다. **공용**만으로 공공 분류하지 않으며, 다른 후보에는 시설 전용 가능성과 이용조건 확인 문구를 강조한다. 실제 이용 가능·무료·실시간 잔여면을 추정하지 않는다.

## 내비 경로 교체 이벤트 보완의 확인 범위

주차장 안내는 실제 순정 내비 화면에서 시작됐지만 앱은 이전 안내의 취소 이벤트를 새 요청 취소로 오인했다. 로그에서 요청 → 이전 경로 취소 → 약 15초 뒤 새 경로 시작 순서를 확인했다. 최신 빌드는 새 요청의 시작 이벤트를 받기 전의 취소 통지만으로 실패를 확정하지 않고 기존 45초 확인 제한을 유지하도록 보완했다. 목적지·경유지 응답 검증은 완화하지 않았다.

보완 후 **기존 강문해변 제2공영주차장 안내가 활성인 상태에서 같은 주차장으로 다시 요청**해 확인했다. 로그는 `00:36:29.074 requested` → `00:36:45.682 route started` → `00:36:46.895 순정 내비에서 목적지 설정을 확인했어요.` 순서였다. 새 경로 시작 후 SDK 목적지 응답 확인까지 완료했으며 이전 안내 취소로 실패를 잘못 표시하지 않았다. 이 사례는 경유지가 없는 주차장 직행이므로, 이전 사진 경유 검증에서 관측한 경유지 좌표 `0/0` 한계가 해결됐다는 뜻은 아니다.

AAOS의 DocumentsUI 선택 문제를 수정한 최신 APK에서 다음 흐름을 확인했다.

1. DocumentsUI 파일 선택기로 영상을 가져왔다.
2. 영상의 **3초~6초** 구간을 선택하고 **도시의 밤** 음악과 메모를 적용했다.
3. 선택 구간 3초와 안내 3초를 합한 **6초 MP4**를 생성하고 앱에서 재생했다.
4. MediaStore로 저장했다. 출력은 **H.264/AAC, 360×640, 765,081바이트**다.
5. 같은 파일을 다시 가져왔을 때 중복으로 추가되지 않고 기록 1개를 유지했다.
6. 앱을 강제 종료한 뒤 다시 열어 촬영일·여정·선택 구간·음악·메모·저장 결과가 보존된 것을 확인했다.

이 흐름의 로그에서 AndroidRuntime 오류는 없었다. 검증에 사용한 입력 영상은 공개 사진을 합성한 테스트 샘플이며 **실제 차량 촬영 영상이 아니다**. 움직이는 영상 파일의 가져오기·구간 편집·인코딩·재생·저장 경로를 확인한 것이며 차량 카메라·GPS 기반 자동 촬영을 검증하지 않았다. 새 영상은 촬영 메타데이터 날짜를 우선하고 없으면 가져온 날짜를 사용하며, 기존 기록은 기존 기록일을 유지한다.

## 실제 순정 내비와 여정 연결

- 별도의 앱 화면 검증에서 서울시청 공개 출발, 복귀 켜짐·체류 0분으로 **세종대로 역사 명소 드라이브**(경성 부민관 폭탄 의거지 → 덕수궁 대한문, 15분·2.8km)를 생성했다. 위 22.33분 API 검증과 다른 실제 요청이며 조회 결과는 달라질 수 있다.

# 최신 검증 · 비동기 취소·입력·저장 오류 수정 · 2026-11-05

## 수정 및 재현

- 서버: 분할 수신한 UTF-8 한글 JSON이 깨지는 문제, null 코스 요청의 500 오류, 빈 좌표·반경의 암묵적 기본값, 잘못된 Kakao/TourAPI 응답의 오분류 수정. 모의 공급자로 재현 후 회귀 검사 통과.
- Android: Future 취소만으로 HTTP 읽기가 중단되지 않아 작업자 두 개를 점유하는 문제 수정. 요청 소유자가 실제 연결을 끊으며, 이미 취소한 작업은 새 HTTP를 시작하지 않는다. 오류 응답 전 getErrorStream 호출로 요청이 시작되는 정리 경로도 수정.
- 웹: 저장된 필터와 다른 첫 선택 코스, pagehide 이후 늦게 도착한 추천·도로 응답의 적용 수정.
- 오디오: 지연된 start/play가 pause·cleanup·소스 교체를 되돌리는 경쟁 상태, 오래된 플레이어 이벤트, 실패 후 잘못된 재생 상태 수정.
- IndexedDB: blocked 이후 늦게 열린 연결 누수, 닫힌 연결 재사용 및 이전 연결의 이벤트가 새 연결을 지우는 문제 수정.
- 공급자 응답 시간 초과를 일반 오류와 구분해 HTTP 504로 반환하고, Android에서 지연 안내를 표시한다. 10초 제한과 자동 호출 횟수는 유지한다.
- API 설정에 기본 주소 복원 버튼을 추가했다. 저장 전 값을 확인할 수 있으며 사용자 정의 주소는 계속 입력할 수 있다.

Android Studio 기기 관리자에서 Graphics acceleration을 Software로 바꾸고 Cold Boot했다. 기존 데이터 초기화 없이 부팅 및 최신 앱 설치 성공, Asta Sans가 적용된 첫 화면·설정 대화상자를 확인했다. 이전 강제 종료 이후 처음으로 실행 화면을 확인한 결과다. Software 렌더링에서 표시·입력 지연을 확인했다. 전국 코스 목록과 Kakao SDK의 줌·로고까지는 표시됐으나 좌표·타일 완료 전에 SCENIC 화면이 닫혔다. 이어 Pleos 기본 차량 화면도 검게 표시됐다. Android Studio Logcat에서 `ai.umos.drivingview`의 `GameThread`가 `libUnreal.so`에서 SIGSEGV를 반복하고, `eglCreateContext: EGL_BAD_CONFIG: no ES 3.2 support`가 출력되는 것을 확인했다. 이 결과를 SCENIC Java 예외로 단정하지 않는다. 이 Software 시도에서는 지도 최종 표시 성공을 검증하지 못했다.


이후 SDK Manager에서 Android Emulator **37.2.13** 패치를 설치하고, Graphics **Hardware(host)** · **Cold Boot** · **RAM 4 GB**로 다시 실행했다. Pleos 차량 화면과 SCENIC가 함께 표시됐으며, 전국 코스의 **지도 제목·Kakao 실제 타일·명소 마커 4개** 표시를 확인했다. 이전 Software 시도의 회색 지도와 구분한다. 장시간 안정성과 실차는 별도 검증 대상이다.

최신 설치본에서 문경 코스를 선택한 상태로 음악 탭을 열어 AI 추천 **Lost in the Woods / Indie Folk Central**을 확인했다. **노래 재생 → 동일한 YouTube Music 공식 플레이리스트 제목·표지·곡 목록 표시 → 닫기 → 코스 화면 복귀**를 직접 확인했다. 로그인과 실제 음원 재생 성공을 의미하지 않는다.

마지막 HTTP 504 안내 변경을 포함한 APK를 Android Studio에서 다시 설치했다(설치 완료 5초 910ms). 동일 문경 코스의 도로 조회에서 **응답 지연 안내**가 실제 표시됐으며, 후속 재시도에서는 **Kakao HTTP 200 / result_code 0 / 약 7.7초** 응답과 **지도 위 실제 도로선** 표시를 확인했다. 임시 진단은 요청 상태·시간과 비식별 해시만 기록했으며 종료 후 일반 `npm start` 서버로 복원했다. 최초 두 번의 일반 오류 원인을 모두 같은 지연으로 단정하지 않는다. 동일 좌표의 별도 로컬 요청 3회도 HTTP 200이었다(988점 / 46.595km / 78.4167분).

전체 UI 검증 중 최종 그래픽 설정에서는 차량 화면과 SCENIC 화면을 유지했다. 외부 API의 일시적 지연은 재발할 수 있고 장시간 연속 구동·실제 GPS 이동·실차 음원 재생은 이번 확인 범위 밖이다.

- 음악 탭은 코스를 만들기 전에도 데모 버튼을 제공했다. 실제 클릭 후 `이 기기에서 YouTube Music을 열 수 없습니다` 안내를 확인했다. 공식 앱 및 HTTPS 링크 시도가 모두 처리되지 않아 이 Pleos 환경의 외부 화면 이동·음악 재생 성공은 확인하지 못했다. 수신 가능한 앱/브라우저 준비가 필요하다.
- 사용자가 Node 서버를 재시작했고 새 API 요청이 실제 처리됐다. 마지막 화면은 성공한 서울시청 기준54분 코스다.

남은 확인: 실제 국내 GPS로 시작하는 실UI 성공 경로, 모든 후보의 현장 진입·영업·주차, 호환 음악 앱/브라우저에서 이동·로그인·재생, 다양한 화면 크기와 실차. 위치 갱신·오래된 응답·시간 경계는 자동 검사로 확인했다. 아래 기록은 이전 버전의 별도 이력이다.

## 구현과 실제 원자료

- TourAPI `KorService2/areaBasedList2` HTTPS 실조회에 성공했다. URL 인코딩된 인증키를 중복 인코딩하던 문제를 수정했다. 키 값·키가 포함된 URL은 로그나 배포 파일에 넣지 않았다.
- 수집 시각2026-11-04 12:16:35 UTC, 원응답4,269건 → 유효·고유 관광지4,264곳. 최종 코스에는1,822곳을 이용했다.

- 미리 계산한 거리·시간은 추정값이다. 실제 도로·통제·영업시간·주차·차량 진입 검증은 아니다. 자세한 가정과 재현은 `catalog/README.md`에 있다.

## 이번 Pleos 화면 확인

Android Studio Run으로 **Pleos Connect v2.1.0 / Android14 API34**에 설치했다. 설치 완료 표시는 **1초383ms**였다.

- 새 `내 위치로 추천`, 지역선택, 반경선택, 전체·호수/숲·바다·도시/문화, 선택형AI UI와 TourAPI680+기존3 표기 확인.
- 초기 전국 둘러보기·120분에서679개 후보, 상위12개 표시 안내와 선택한 새 코스의 실제 Kakao지도·명소 마커 확인.
- `내 위치로 추천`을 누르면 에뮬레이터 GPS ±5m를 수신했고, 국내 추천 범위 밖이라는 안내와0개 후보를 표시했다. 오래된 이전 코스 지도/시작 버튼이 남지 않는 상태를 확인했다. 이 좌표는 에뮬레이터 설정이며 사용자의 실제 위치 검증이 아니다.
- 지역선택 대화상자에서 경기 선택 →120분에서40개 후보와 김포 코스 지도 확인.

국내 GPS 좌표를 에뮬레이터에 주입한 실UI 성공 경로는 이번에 확인하지 않았다. 국내 위치별 추천·접근시간 포함은 pure Java엔진 검사로 확인했다.

## 검토 후 수정한 상태 문제

- 우도·가파도/마라도·추자도 출발을 제주 본섬까지의 단순 자동차 접근으로 계산하지 않도록 제외 안내와 검사를 추가했다.
- 시간1분 등 빈 결과에서 음악·북마크·영상이 화면에 숨겨진 이전 코스와 연결되지 않도록 차단했다. 영상 선택에서 복귀한 뒤와 비동기 메타데이터 처리 후에도 조건을 다시 검사한다.
- GPS가 없거나 오래된 경우의 영상 제한과, 정차 중 지역탐색/API조작 조건을 분리했다. 실제 이동·진행중 여정·차량 UX 제한은 유지한다.
- 위치·필터·코스 변경 이후 AI응답은 요청 세대와 후보 revision으로 무효화하며, AI응답 도착 시 위치 신선도도 다시 검사한다.
- AI에 전달하는 후보는 등록된 ID최대12개다. 비공개 키와 GPS원본은 전송하지 않고 대략적인 관심지역이 후보에서 드러날 수 있음을 UI에 안내한다.

## 이전에 확인한 동작과 현재 남은 범위

이전 버전에서는75분 직접 입력·0분 오류 처리, 에뮬레이터 GPS수신, 외부음악 수신 앱 없음 안내, 실제OpenAI추천과 Kakao18.1km·34분 도로 응답을 확인했다. 지도는 Pleos차량설정의 AndroidWifi연결로 복구해 실제타일·코스마커를 확인했고 이번 새코스 화면에서도 유지됐다.

기본 전국추천은 서버 없이 동작한다. **새 서버 카탈로그/AI추천을 실제로 이용하려면 실행중인 이전 Node서버를 종료하고 `npm start`로 재시작해야 한다.** 현재 실행중인 서버의 프로세스는 이 작업에서 재시작하지 않았다. 지도페이지는 기존 실행중인 서버로 표시됐다.

남은 확인: 모든680코스의 실제 도로 연결·주차·영업시간, 국내 에뮬레이터 GPS를 주입한 UI시험과 실기기GPS, 위치권한 거절·오래됨의 실UI시나리오, 새카탈로그 실제AI응답, 호환음악앱 실제재생, 영상공급자/코덱, 정차→주행 실전환, 다양한해상도·최대글꼴, 실차·스토어 검증.
