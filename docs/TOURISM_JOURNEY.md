# 지역에서 풍경·맛집·주차로 이어지는 드라이브

기본 발견 화면은 **지역 → 실제 풍경 사진 → 관광지 목적지 → 주변 식당 → 주차장 안내** 흐름이다. 사진으로 선택한 관광 장소가 목적지이며, 처음 고른 지역의 중심점으로 돌아오는 경로를 자동으로 추가하지 않는다. 기존 **고정 목적지 앞에 사진 장소를 경유하는 모드**는 별도 목적지 검색에서 유지한다.

## 1. 여행 지역 선택

첫 화면에는 다음 8개 탐색 지역을 제공한다.

| 지역 | 사진 검색 중심 권역 |
|---|---|
| 강릉 | 경포권 |
| 속초·양양 | 낙산권 |
| 여수 | 돌산·여수 해안권 |
| 남해 | 삼동·물미해안권 |
| 경주 | 보문·경주 시내권 |
| 제주 동부 | 구좌·동부 해안권 |
| 부산 해안 | 해운대·동부 해안권 |
| 가평 | 가평·북한강권 |

지역 카드의 풍경 그림은 **여행 테마 일러스트**다. 실제 지역 사진이나 현장에서 검증한 드라이브 도로로 표시하지 않는다. 카드의 소개·음식 힌트에는 관광기관 출처가 있으며, 코드의 `DriveRegion`에 지역별 출처 링크를 보관한다. 음식 힌트는 검색 선택지이며 특정 식당의 품질·메뉴 보유를 보증하지 않는다.

**다른 지역 검색하기**로 도시·여행 지역을 직접 찾을 수도 있다. 사진 조회는 선택한 탐색 중심의 반경 5·10·20km를 사용하므로 행정구역 전체를 검색하거나 해당 지역 경계 안만 보장하는 기능은 아니다. 예를 들어 제주 동부 선택은 제주도 전역 검색을 뜻하지 않는다.

## 2. 실제 공개 사진의 적합성 확인

TourAPI에서 좌표·공공누리 제1유형 이용 조건·공식 이미지 URL을 확인한 관광 사진을 가져온다. 장소 메타데이터로 명백한 실내 시설, 단독 기념물, 도보·등산 중심 장소 등을 제외하고 풍경 단서가 있는 후보를 우선해 최대 12개를 이미지 평가에 사용한다.

위치 기반 목록의 후보가 적을 때는 배포된 원본 TourAPI 스냅샷과 카탈로그에서 가까운 장소 **ID만** 조회 단서로 얻는다. 최대 8개 ID를 동시 3개 이하로 최신 `detailCommon2`에 조회하며, 응답 ID 일치·현재 좌표·반경·제1유형 이용 조건·공식 이미지 URL·장소 적합성을 다시 확인한다. 제한 시간 안에 확인하지 못한 후보는 넣지 않고 일부 최신 사진을 확인하지 못했다는 상태를 표시한다. 이전 사진·좌표를 그대로 결과로 내보내거나 제3유형으로 라이선스 범위를 넓히지 않는다.

OpenAI에는 실제 공개 썸네일 이미지와 장소명·식별자를 전달한다. 사진에서 넓은 풍경을 감상할 수 있는지, 실내·상품·안내판·인물·건물 외관 중심인지 구분한다. 정상 평가에서는 풍경 적합 판정·점수 55 이상·구체적 풍경 유형을 모두 충족한 사진만 표시한다. 이 점수는 사진 구성에 대한 AI 평가이며 실제 도로 구간의 조망 점수가 아니다.

AI 호출이나 응답 검증에 실패하면 메타데이터 필터를 거친 공개 후보를 **거리순·AI 사진 분석 미사용**으로 표시한다. AI가 부적합하다고 분류한 사진을 결과 수를 채우기 위해 다시 넣지 않는다. 결과가 없으면 반경을 넓히거나 다른 지역을 고를 수 있다. 지역 중심으로 바로 가는 별도 버튼은 사용자가 직접 눌러야 한다.

사진 제공은 **TourAPI**, 사진 평가는 **OpenAI**다. Pleos의 **Gleo 사진 검색·비전 API를 호출하는 구현은 아니다**. 개인 사진·영상은 이 평가에 사용하지 않는다.

## 3. 선택한 사진의 장소로 이동

**이 풍경 보러 가기**를 누르면 사진의 관광 장소가 최종 목적지가 된다. 지역 중심은 검색 맥락으로 남기고 목적지나 경유지로 자동 추가하지 않는다.

서버가 발급한 사진 선택 토큰은 해당 탐색 지역과 선택한 관광 장소에 연결된다. 사진 장소를 요청자가 임의 좌표로 바꾸지 못하게 검증하며, 30분이 지나거나 서버가 재시작되면 다시 사진을 불러와야 한다. 도로는 Kakao로 별도 조회하고, 반환 도로의 끝점이 선택한 관광 장소 좌표 150m 이내인지 확인한다. 확인할 수 없으면 지역 중심이나 다른 관광지로 바꾸지 않고 오류를 안내한다.

사진 좌표는 **관광 장소의 대표 위치**다. 정확한 촬영 지점·방향·시기, 현재 차창 조망, 주차장 입구를 확인한 것은 아니다. 도로 끝점이 가깝더라도 실제 진입 규정·현장 통행·최종 도보 접근까지 검증했다는 뜻은 아니다.

순정 내비를 요청하면 Pleos NaviHelper가 선택 장소를 전달한다. Pleos는 차량 현재 위치에서 다시 탐색하므로 앱의 공개 시연 출발지나 Kakao 경로선·예상 시간과 달라질 수 있다.

## 4. 관광지 주변 식당 선택

관광지 경로 화면의 **다음 · 이 풍경 주변 맛집 찾기**를 누르면 그 관광 장소 주변 3km의 식당을 조회한다. 전체 음식점은 음식점 분류(FD6)의 거리순이며, 음식 힌트를 선택하면 Kakao 키워드 검색에서 실제 **음식점(FD6)·카페(CE7)**로 분류된 결과만 관련도순으로 표시한다. 따라서 커피·황남빵 같은 검색에서도 카페를 제외하지 않는다. 관광지·쇼핑 시설·분류 미확인 결과는 키워드 목록에서 제외한다. 등록된 분류·전화·주소·직선거리만 보여 주고 리뷰 점수나 별점을 생성하지 않는다. 검색 결과가 없을 때 다른 음식으로 조용히 대체하지 않는다.

식당을 선택하면 식당 정보만 저장하고 그 식당 좌표를 중심으로 **주차장을 즉시 자동 조회**한다. 이 단계만으로 관광지 목적지를 식당이나 주차장으로 바꾸거나 길 안내를 시작하지 않는다. 자체 주차 여부에 관한 사용자 메모는 별도로 저장할 수 있지만 실시간 상태로 취급하지 않는다.

## 5. 주차장까지의 명시적 안내

가까운 등록 주차장 최대 15개 중 이름에 **공영·공공·시영·구영·군영**이 표시된 곳을 먼저, 같은 분류 안에서는 거리순으로 정렬해 최대 10개를 보여 준다. **공용**이라는 단어만으로 공공 주차장으로 간주하지 않는다. 공공 표기가 없는 곳은 **시설 전용일 수 있음·이용조건 확인 필요**를 강조한다. 첫 결과에 공공 표기가 있을 때만 우선 추천 버튼을 사용하며, 이름의 표기는 실제 개방·빈자리·무료 이용·영업 여부의 확인이 아니다. **추천 주차장까지 안내** 또는 다른 주차장의 안내 버튼을 눌렀을 때만 다음 동작을 수행한다.

1. 주차장을 이번 이동 목적지로 저장한다.
2. 선택한 출발지에서 해당 주차장까지 실제 도로를 조회한다.
3. 도로 응답이 유효하고 정차 상태가 유지된 경우 Pleos 순정 내비로 전달한다.

도로 확인 실패 시 내비를 자동 요청하지 않으며 사용자가 다른 주차장을 고를 수 있다. 원지역·관광지·식당 맥락은 계속 보존하되 관광지를 주차 경로에 자동 경유지로 넣지 않는다. 식당을 선택해 둔 경우 주차 후 방문할 식당과 직선거리도 표시한다.

Kakao 장소 검색은 **현재 잔여 주차면·요금·운영시간·입차 가능 여부**를 제공하지 않는다. 따라서 등록 위치와 도로 응답을 확인해도 “지금 주차 가능”으로 확정하지 않는다. 식당 자체 주차 메모도 사용자 수동 확인 기록이며 현재 빈자리를 보장하지 않는다. 입구·운영 규정·실제 도보 이동은 현장에서 확인해야 한다.

## 저장·취소·주행 제한

여정은 출발지, 원지역, 선택한 관광지, 식당, 주차장, 현재 이동 목적지를 구분해 저장한다. 새 지역이나 관광지를 고르면 이전 식당·주차장 선택을 정리한다. 기존 버전의 여정도 지역을 임의로 만들어 넣지 않고 복원한다.

사진·주변 장소 요청은 화면을 떠나거나 주행 제한 상태가 되면 취소하고, 늦은 응답이 새 선택을 덮어쓰지 못하게 확인한다. 사진·식당·주차장 선택과 내비 요청은 조작 시점에 정차 여부를 재검사한다. 서버 키는 로컬 `.env`에서만 사용하며 앱·문서·커밋에 넣지 않는다.

## 기존 모드와 검증 상태

별도 **목적지 검색**에서는 원래 목적지를 고정하고 사진의 장소를 경유하는 기존 모드를 유지한다. 이 모드는 빠른 길 대비 추가 시간과 경유 도로를 비교하며, 지역 사진 목적지 모드와 목적지 의미가 다르다. 기존 설명은 [목적지 사진 경유](DESTINATION_PHOTOS.md)에 있다.

2026-11-06의 실제 API·에뮬레이터 화면에서 **강릉 → 경포해수욕장 실제 제1유형 사진·OpenAI 평가 → 사진 장소까지 223km·214분 → 초당두부 → 고향산천초당순두부 → 주차 자동 조회 → 180m 강문해변 제2공영주차장 우선 표시 → 순정 내비의 해당 주차장 199km·2시간 46분 안내**를 확인했다. 관광지 도로의 끝점 150m 검증을 통과했으며 원지역으로 돌아오는 구간은 붙이지 않았다.

Node **207/207**, Java **21개 모음**, 내비 이벤트 구분과 주차장 직행 문구 보완을 포함한 최종 Gradle 빌드 **34초**가 통과했고 APK를 재설치했다. 기존 순정 내비 안내 중 다시 요청해 새 경로 시작과 SDK의 목적지 응답 확인을 검증했다. 강제 종료·재설치 후에도 지역·관광지·식당·주차장 선택이 유지됐으며 주차장까지 **220.7km·212분** 직행 경로가 복원됐다. 사진 선택 화면은 자동으로 다시 열리지 않았고 최종 재설치 후 좌측 경로 확인과 우측 직행 문구도 확인했다. 원격 CI는 해당 PR의 GitHub Actions 결과를 기준으로 확인하며 상세 증거·한계는 [검증 기록](VALIDATION.md)에 있다. 기존 서울역 사례는 이전 고정 목적지 모드의 기록으로 유지한다.
